# Руководство разработчика (Developer Guide) — `video_convert`

> Данный документ предназначен для разработчиков и AI-агентов, сопровождающих, модифицирующих или расширяющих кодовую базу **`video_convert`**.

---

## 1. Архитектура проекта и структура файлов

```text
video_convert/
├── src/
│   ├── main.rs               # Точка входа, парсинг CLI, оркестрация процессов
│   ├── installer.rs          # Самоустановка в AppData, версионирование X.Y.Z.B, Add/Remove Programs, деинсталляция
│   ├── dialog.rs             # Нативный Windows Common Item Dialog с IFileDialogCustomize
│   ├── compressor.rs         # Анализ видео, расчёт битрейта, 1-pass/2-pass кодирование, прогресс
│   ├── embedded_ffmpeg.rs    # Распаковка и кеширование встроенного FFmpeg 9.0.1 и иконки app_icon.ico
│   ├── input_box.rs          # Нативное модальное Win32-окно ручного ввода целевого размера
│   └── registry.rs           # Каскадное меню в Windows Registry (в HKCU) и уведомление оболочки через SHChangeNotify
├── app_icon.ico              # Многослойная Windows-иконка (16x16 ... 256x256)
├── build.rs                  # Скрипт сборки: вшивание app_icon.ico в PE-заголовок через winres
├── Cargo.toml                # Конфигурация Cargo, зависимости (windows, winreg, lzma-rs)
├── ffmpeg.xz                 # LZMA-сжатый бинарник FFmpeg 9.0.1 Essentials (~26.2 МБ)
├── CHANGELOG.md              # История версий и изменений
├── README.md                 # Инструкция пользователя
└── DEVELOPER_GUIDE.md        # Текущее руководство разработчика
```

## 2. Модули и их ответственность

### 2.1. `src/main.rs`
- **Задачи**:
  1. Перехват быстрых запросов до баннера (`--get-version` возвращает чистую строку версии `9.0.1.3` для скриптов).
  2. Вывод консольного баннера `print_banner()`.
  3. Парсинг CLI-флагов:
     - `--help` / `-h` $\rightarrow$ справка по всем командам
     - `--version` / `-v` $\rightarrow$ форматированный вывод версии и сборки
     - `--register` / `-r` $\rightarrow$ вызов `installer::install_app()` (копирование в AppData + контекстное меню + Uninstall реестр)
     - `--unregister` / `-u` $\rightarrow$ вызов `registry::unregister_context_menu()` и `installer::unregister_uninstall()`
     - `--uninstall` / `-q, --quiet` $\rightarrow$ вызов `installer::uninstall_app(quiet)`
     - `--target <MB>` / `-t <MB>` $\rightarrow$ целевой размер
     - `--no-pause` / `-y` $\rightarrow$ подавление паузы на выходе
  4. Если файл не передан (обычный запуск):
     - **Проверка установки / обновления**: вызов `installer::check_install_or_update(&current_exe)`. Если программа запущена из внешнего каталога (например, Downloads), пользователю предлагается установить или обновить системную копию.
     - **Немедленное открытие нативного диалога выбора файла** через `dialog::pick_video_file_with_target()`.
     - Пользователь выбирает файл и при необходимости меняет целевой размер в ComboBox (по умолчанию 10 МБ).
     - Сжатие запускается сразу же после нажатия «Открыть», без задержек и консольных таймеров.
  5. Проверка и подготовка FFmpeg (`embedded_ffmpeg::ensure_ffmpeg()`).
  6. Передача управления в `compressor::compress_video()`.

### 2.2. `src/installer.rs`
- **Задачи**:
  - **4-компонентное версионирование (`Version`)**:
    - Структура: `Version { major: u32, minor: u32, patch: u32, build: u32 }`.
    - Поддержка сравнения (`PartialEq`, `Eq`, `PartialOrd`, `Ord`). Номер сборки `build` инкрементируется при каждом релизе фиксов.
    - Парсинг версии из запущенного бинарника или реестра через `Version::parse()`.
  - **Жизненный цикл установки и обновления**:
    - Место назначения: `%LOCALAPPDATA%\VideoConvert\video_convert.exe`.
    - `check_install_or_update(current_exe)`:
      - Если программа уже работает из `%LOCALAPPDATA%\VideoConvert\`, никаких окон не выводится, запуск идёт штатно.
      - Если системный бинарник отсутствует: нативный Win32 `MessageBoxW` предлагает установить утилиту и добавить пункты в ПКМ. При согласии вызывается `install_app()`.
      - Если системный бинарник присутствует: проверяется версия в реестре/бинарнике. Если текущая версия новее установленной, `MessageBoxW` предлагает обновиться. При согласии обновляется бинарник, иконка, реестр и обновляется кэш оболочки.
  - **Интеграция с «Установка и удаление программ» Windows**:
    - Ключ реестра: `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\VideoConvert`.
    - Параметры: `DisplayName`, `DisplayVersion`, `Publisher`, `InstallLocation`, `DisplayIcon`, `UninstallString`, `QuietUninstallString`, `EstimatedSize`, `NoModify`, `NoRepair`.
  - **Деинсталляция (`uninstall_app`)**:
    - Очистка контекстного меню в `HKCU\Software\Classes`.
    - Удаление записи из `Uninstall\VideoConvert`.
    - Обновление кэша оболочки Windows через `registry::refresh_shell()`.
    - Отложенное самоудаление папки `%LOCALAPPDATA%\VideoConvert\` в фоновом процессе через `cmd.exe /c ping 127.0.0.1 -n 2 > nul & rmdir /s /q ...` (если файлы заблокированы текущим процессом).


### 2.3. `src/dialog.rs`
- **Задачи**:
  - Реализация интерфейсов `IFileOpenDialog` и `IFileDialogCustomize` из Windows Common Item Dialog API.
  - Реализация интерфейсов событий `IFileDialogEvents` и `IFileDialogControlEvents` через `DialogEventHandler`.
  - Добавление двух чистых визуальных групп с ComboBox:
    - `Целевой размер:` (1, 2, 3, 5, 7, 10, 15 МБ и `Другой размер...`). Фокус по умолчанию на `10 МБ`.
    - `Масштаб картинки:` (от 100% до 25% с шагом 5%). По умолчанию `100%`.
  - **Динамическое поле ввода в том же окне**:
    - Контролы `ID_LABEL_CUSTOM` («Укажите размер (МБ):») и `ID_EDIT_CUSTOM` (текстовое поле) по умолчанию находятся в состоянии `CDCS_INACTIVE` (скрыты и неактивны).
    - При выборе пункта `Другой размер...` метод `OnItemSelected` переводит их в `CDCS_VISIBLE | CDCS_ENABLED` — поле ввода активируется прямо в этом же окне Проводника.
    - При переключении обратно на стандартные пресеты они возвращаются в `CDCS_INACTIVE`.
  - При нажатии «Открыть» значение считывается через `GetEditBoxText` (если выбран «Другой размер...») либо берётся из пресета.

### 2.4. `src/input_box.rs`
- **Задачи**:
  - Отображение легковесного модального Win32 диалогового окна запроса произвольного размера в МБ (`show_input_box`).
  - Создание нативного окна через `CreateWindowExW`, системного шрифта `DEFAULT_GUI_FONT`, поля `EDIT` с предзаполненным значением `10` и кнопок `ОК` / `Отмена`.
  - Поддержка горячих клавиш (Enter — подтверждение, Esc — отмена).
  - Используется при вызове через контекстное меню ПКМ (пункт `Другой размер...`), так как при ПКМ диалог выбора файла не открывается (файл уже выбран в Проводнике).

### 2.5. `src/compressor.rs`
- **Задачи**:
  - `probe_video(ffmpeg, input)`: Запуск `ffmpeg -hide_banner -i <file>` и парсинг stderr:
    - Длительность (`Duration: HH:MM:SS.ss`).
    - Наличие звуковой дорожки (`Audio:`).
    - Разрешение (`\d+x\d+`).
  - **Защита от раздувания (`Output <= Input`)**:
    - Если `input_len <= max_target_bytes`, немедленно возвращает `Ok(input)` с предупреждением о бессмысленности сжатия.
    - В конце кодирования, если `out_len >= input_len`, удаляет созданный файл и возвращает ошибку.
  - `plan_encoding(meta, target_mb)`:
    - Целевой размер в байтах с запасом 6% на служебные заголовки MP4:
      $$\text{target\_bytes} = \text{target\_mb} \times 1024 \times 1024 \times 0.94$$
    - Доступный битрейт:
      $$R_{total} = \frac{\text{target\_bytes} \times 8}{\text{duration\_secs}}$$
    - Адаптивный аудиобитрейт $R_{audio}$ (48, 64, 96, 128 кбит/с в зависимости от размера и длины).
    - Видеобитрейт $R_{video} = \max(R_{total} - R_{audio}, 32 \text{ кбит/с})$.
    - Умное масштабирование:
      - $R_{video} \ge 1400$ кбит/с $\rightarrow$ `scale='min(1920,iw)':-2`
      - $650 \le R_{video} < 1400$ кбит/с $\rightarrow$ `scale='min(1280,iw)':-2`
      - $300 \le R_{video} < 650$ кбит/с $\rightarrow$ `scale='min(854,iw)':-2`
      - $R_{video} < 300$ кбит/с $\rightarrow$ `scale='min(640,iw)':-2`
    - **Выбор режима проходов**:
      - Длительность $\le 12$ сек ИЛИ $R_{video} \ge 5000$ кбит/с $\rightarrow$ `PassMode::SinglePass`.
      - Иначе $\rightarrow$ `PassMode::TwoPass`.
  - **Кодирование и прогресс-бар**:
    - FFmpeg при `-stats` выводит прогресс через символ возврата каретки (`\r`).
    - `run_with_progress` читает stderr через `read_until(b'\r', &mut buf)`, парсит `time=HH:MM:SS.ss` и отрисовывает псевдографический прогресс-бар (`[████░░░░] XX%`) со скоростью кодирования.
    - Если FFmpeg возвращает ненулевой код, накопленный буфер последних сообщений об ошибках выводится пользователю.

### 2.6. `src/embedded_ffmpeg.rs`
- **Задачи**:
  - Хранит байты сжатого FFmpeg: `static FFMPEG_XZ: &[u8] = include_bytes!("../ffmpeg.xz");`.
  - Хранит байты иконки: `static APP_ICON: &[u8] = include_bytes!("../app_icon.ico");`.
  - Проверяет существование файла `%LOCALAPPDATA%\VideoConvert\bin\ffmpeg_9.0.1.exe`.
  - Проверяет целостность по размеру (`EXPECTED_SIZE = 102856192` байт).
  - Если файл отсутствует или поврежден:
    - Распаковывает `FFMPEG_XZ` во временный файл `ffmpeg_9.0.1.tmp` через `lzma_rs::xz_decompress`.
    - Выполняет атомарное переименование `fs::rename` в целевой исполняемый файл.
    - При повторных запусках извлечение пропускается (старт 0 мс).
  - `ensure_icon()`: гарантирует наличие чистой иконки `%LOCALAPPDATA%\VideoConvert\app_icon.ico` для системного контекстного меню и апплета «Установка и удаление программ».

### 2.7. `src/registry.rs`
- **Задачи**:
  - Создание статического каскадного контекстного меню Windows Explorer без прав администратора (ветка `HKEY_CURRENT_USER`).
  - **Структура ключей**:
    - Все команды контекстного меню (`command`) жестко привязаны к `%LOCALAPPDATA%\VideoConvert\video_convert.exe`, защищая ассоциации от перемещения исходного установщика.
    - Родительский ключ `CompressVideo` содержит `MUIVerb = "Сжать видео"`, `SubCommands = ""`, `Icon = "%LOCALAPPDATA%\VideoConvert\app_icon.ico"` (иконка только здесь!).
    - Значение `(Default)` удалено/отсутствует.
    - Вложенное поддерево `CompressVideo\shell\01` ... `08` содержит отдельные пресеты (1, 2, 3, 5, 7, 10, 15 МБ и «Другой размер...») с параметрами `MUIVerb` и `(Default)`.
    - **Важно**: у подпунктов параметр `Icon` отсутствует (чистые аккуратные строки без повторяющихся иконок).
    - **Поддержка Windows 11**: регистрация ключа `HKCU\Software\Classes\CLSID\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}\InprocServer32` обеспечивает прямой показ классического меню при первом правом клике без «Показать дополнительные параметры».
  - `refresh_shell()`: вызов официального системного Windows Shell API `SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST | SHCNF_FLUSH, None, None)` для мгновенного сброса кэша ассоциаций Проводника без моргания экрана, закрытия открытых окон и перезапуска `explorer.exe`.

## 3. Сборка и профили оптимизации

В `Cargo.toml` настроен экстремальный профиль уменьшения размера исполняемого файла:
```toml
[profile.release]
opt-level = "z"       # Оптимизация по размеру (size)
lto = true            # Link-Time Optimization во всем графе зависимостей
codegen-units = 1     # Монолитная кодогенерация для максимального сжатия
panic = "abort"       # Отключение раскрутки стека при панике
strip = true          # Удаление всех отладочных символов из финального PE
```

Для вшивания иконки используется `build.rs` и crate `winres`:
```rust
#[cfg(windows)]
fn main() {
    let mut res = winres::WindowsResource::new();
    res.set_icon("app_icon.ico");
    res.compile().unwrap();
}
```

### Команда сборки:
```cmd
cargo build --release
```
Результирующий бинарник: `target\release\video_convert.exe` (~26.5 МБ).

## 4. Важные технические нюансы (Gotchas & Best Practices)

1. **Каскадные меню Explorer и значение (Default)**:
   - Если у родительского ключа контекстного меню установлено значение `(Default)`, Windows Explorer пытается найти подключ `command` и выполнить его. В результате стрелка подменю не отображается, а при клике ничего не происходит. Для каскадного подменю значение `(Default)` **обязано отсутствовать**, а название меню должно задаваться исключительно через `MUIVerb`.
2. **Предотвращение дублирования строк в каскадном меню**:
   - Нельзя одновременно указывать `ExtendedSubCommandsKey` и вложенный раздел `shell`. Explorer парсит оба источника и отображает каждый пункт дважды. Используется каноническое вложенное дерево `shell` с пустым `SubCommands = ""`.
3. **Иконка только на корневом элементе**:
   - Параметр `Icon` должен задаваться только на основном ключе `CompressVideo`. У подпунктов `01..07` параметр `Icon` не задаётся.
4. **IFileDialogCustomize и нативный UI**:
   - `IFileDialogCustomize` позволяет встраивать контролы (`AddComboBox`, `StartVisualGroup`) в нативный диалог открытия файлов до вызова `Show()`. Это избавляет от необходимости поднимать тяжеловесные UI-фреймворки или использовать консольные задержки.
5. **Согласованность параметров в 2-pass libx264**:
   - Параметры `-preset`, `-vf` (масштабирование) и b-frame настройки **обязаны строго совпадать** между Pass 1 и Pass 2.
6. **Парсинг прогресса через `\r`**:
   - FFmpeg не выводит `\n` для прогресса, а перезаписывает строку через `\r`. Чтение потока stderr производится через `read_until(b'\r', ...)`.
7. **Блокировка исполняемых файлов при обновлении в Windows**:
   - Работающий `.exe` файл в Windows заблокирован ядром ОС на перезапись и прямое удаление. Поэтому процедура обновления в `installer.rs` сначала пытается перезаписать файл, а при блокировке выполняет ротацию: переименовывает заблокированный файл в `.old_tmp`, копирует новую версию и помечает старый файл на удаление.
8. **Отложенное самоудаление каталога при деинсталляции**:
   - При деинсталляции через `--uninstall` текущий процесс не может удалить собственный каталог, пока открыт дескриптор PE-образа. Для гарантированной очистки порождается фоновый непривязанный командный процесс: `cmd.exe /c ping 127.0.0.1 -n 2 > nul & rmdir /s /q "%LOCALAPPDATA%\VideoConvert"`, который ожидает закрытия процесса и начисто удаляет директорию.
9. **Синхронизация с FFmpeg и инкремент сборок (`9.0.1.XXX`)**:
   - Базовая версия `9.0.1` жестко привязана к версии встроенного кодека FFmpeg 9.0.1.
   - В `src/installer.rs` задана константа `Version::CURRENT = Version::new(9, 0, 1, 3);`.


   - Для любых промежуточных релизов или исправлений ошибок инкрементируется поле `build` (четвертый компонент: `9.0.1.1`, `9.0.1.2`, ...). Алгоритм сравнения версий (`installed_ver < Version::CURRENT`) автоматически распознает новый билд и предлагает пользователю обновиться в один клик.
